# Jutland 设计地图关卡

## 核心规则

- 把“历史考据”“地图尺度”“游戏部署”分成三个可独立验证的层次；不要用布阵微调掩盖地图比例错误，也不要在未经审计的地图上直接照图撒点。
- 写 `configs/missions.json5` 前完成比例审计；地图地标与舰船相对尺度明显错误时，先报告并确认修图或游戏化近似方案。不要只放大舰船贴图修复尺度。
- 明确关卡快照时间，例如“1941-12-07 07:55”；不要混用战斗开始前、受击后或已起航舰船的位置，不得在缺少快照时间、证据和网格近似说明时声称“历史精确”。
- 历史舰不存在时，按“同名 -> 同级 -> 同类别且吨位/尺寸接近”替代，保持舰种不变（不以战列巡洋舰替代轻巡），并逐舰在 JSON5 注释中写明历史舰名、替代资源和理由。
- 舰首朝向使用游戏约定：`0°=北`、`90°=东`、`180°=南`、`270°=西`；区分舰首方向、泊位轴线和图片箭头方向。
- 港池、码头和干船坞在粗网格中可能变成岸格：允许移动到最近可航行格，但必须保持纵向顺序、内外舷关系和历史朝向，并在配置中说明；舰体中心位于水面不等于完整通过，还要检查舰首、舰尾和并靠间距。
- 只部署用户要求的舰种；辅助舰、潜艇、岸防设施和增援点不得因史料中出现而自动加入。
- 敌我舰队不得无意中过近：布阵后同时计算双方编队质心距离和最近敌我舰距离。无特殊设定时，最近敌我警戒舰至少相隔 50 格（约 6.4km）；航母战若地图允许，双方航母或主力编队宜相隔 80–100 格（约 10.2–12.8km），并确认舰载机仍可抵达目标。史实近战、伏击或用户明确要求开场进入射程可以例外，但必须在配置注释和交付说明中写明原因；每次舰位调整后重新计算敌我最短距离。
- `initCameraPos` 默认对准玩家阵营初始舰位的算术质心，而不是地图中心、双方战场中点或敌军方向；舰位全部确定后计算 `round(sum(x)/n), round(sum(y)/n)`。玩家有多个远离的分舰队时，改用开场最需要操作的主力编队质心并在配置注释中说明例外；舰位变更后不得沿用旧值。

## 工作流程

1. **确认范围。**
   - 定义地图、年代、阵营、玩家方、敌方、部署舰种、是否包含增援和胜负玩法。
   - 检查 `configs/maps.json5`、`resources/maps/<map>.map`、`resources/images/map/abbrs/<source>.png` 是否完整一致。

2. **审计地图尺度。**
   - 读取网格宽高、PNG 尺寸和 `constants.MapBlockSize`，计算游戏逻辑范围 `网格格数 × MapBlockSize`。
   - 选择至少一个已知真实尺寸的地标和一型已知舰长，比较“地标长度/舰长”的历史比值与游戏比值。
   - 同时检查长轴和短轴：两者误差接近通常是整体缩放问题，只有一轴错误通常是非等比拉伸。
   - 查看 `pkg/resources/images/mapblock/block.go` 的地图块缩放，不把源 PNG 像素数直接当成游戏米制。
   - 详细方法和珍珠港案例见 [references/design-rules.md](references/design-rules.md)。

3. **建立历史锚点。**
   - 优先使用官方战斗报告、海军舰位图、同时期垂直航拍和港务泊位图；二手资料只用于补缺。
   - 先标地标、泊位和编队中心，再放单舰，记录证据、时间点、估算误差和朝向来源。
   - 参考图坐标映射到游戏网格时至少使用两个方向上的控制点；地图有旋转或形变时使用仿射变换，不只按截图宽度等比换算。

4. **盘点舰船资源并确定替代。**
   - 从 `configs/ships.json5` 获取名称、国家、类型、级别线索、长度和吨位；同级替代优先于吨位近似。
   - 吨位接近时再比较长度、年代、航速和武器角色。
   - 为每艘历史舰维护一条显式映射，不依赖相同资源名的重复次数表达身份。

5. **写入任务。**
   - 沿用相邻关卡字段和 JSON5 风格，最小修改 `configs/missions.json5`。
   - 为新任务补齐四种显示名和描述：`displayName`、`displayNameEn`、`displayNameRu`、`displayNameJa`。
   - 先写防守方历史泊位，再写进攻方编队；按舰种和泊位组分段。
   - 注释至少包含历史舰名/编号、实际资源名、替代原因、泊位或编队位置、舰首方向。
   - 舰位完成后计算双方质心距离、最近敌我舰距离，以及航母战的最近敌我航母距离；距离不足时优先整体平移编队并保持内部队形不变，再重新检查边界、岸格和舰载机航程。
   - 用最终舰位计算玩家阵营质心并写入 `initCameraPos`：单一编队四舍五入到最近网格，多个远离编队则聚焦开场主力编队。
   - 无增援或油井时使用空数组。

6. **验证并交付。**
   - 手工核对：双方舰数、双方质心距离、最近敌我舰距离、`initCameraPos` 与玩家质心偏差（单一编队 ≤ 1 格；有分舰队例外时镜头须落在指定主力编队内）、重复坐标、舰体边缘压岸警告逐项审阅。
   - 运行 `git diff --check -- configs/missions.json5`、相关包测试、`go test ./...` 和 `go build ./...`。
   - 若环境可启动窗口，手动检查地图比例、舰体重叠、首向、初始镜头和 AI 可达路径。
   - 最终说明双方舰数、替代策略、尺度结论、开场舰距、初始镜头坐标、粗网格位移、实际验证和未做的视觉运行检查。
