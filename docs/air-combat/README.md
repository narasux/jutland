# 空战 AI 与轰炸机自卫火力修复方案（设计稿）

> 状态：设计稿，未实现。本文只定义目标行为、拆分和验收口径，供后续迭代使用。
>
> 背景：`MidwayAllTypesDuelTest`（海空全机型对决-中途岛）在 F3 AI vs AI 下，轴心国
> 3 个 seed 全部被打成 31/31 或 26/31 沉没、同盟国 0 沉没；首分钟轴心国损失约 210 架
> 战斗机，全程 884 架战斗机损失中约 47% 死于同盟国轰炸机/攻击机的自卫火力。把双方
> 舰队向地图中心移动、让所有舰载机都能出击之后，轴心国仍然 31/31 沉没，说明问题不只是
> 航程门槛，而是**空战没有指挥层，所有飞机按单机目标自由交战**。

---

## 1. 问题定义

### 1.1 观测到的行为

| 现象 | 数据（seed 1，P2=轴心国） |
|---|---|
| 首次接触 | 约 18 s |
| 首分钟战斗机损失 | 轴心约 212 架 / 同盟约 110 架 |
| 到 120 s 战斗机累计损失 | 轴心约 795 架（约 90% 战斗机兵力） |
| 轴心战斗机总损失 | 884 架，其中 467 架死于同盟战斗机、416 架死于轰炸机/攻击机 |
| 轴心对舰命中 | 正式局 0；旁路局仅 3 枚 Ar234B 炸弹 |
| 同盟对舰命中 | 约 300 枚炸弹 + 49 枚鱼雷，31 艘航母在 60 s 内沉没 |
| 首艘航母沉没 | 约 128 s |
| 战斗结束 | 2:30–3:10，没有第二波、没有残存航空兵力再战 |

舰队向中心移动后（本关两列相距约 93 格，全部舰载攻击机可出击），轴心国仍然 31/31 沉没，
只是把 451 架随舰损失降到 75 架。**航程门槛解决的是“飞机能不能起飞”，解决不了
“起飞之后怎么打”。**

### 1.2 根因

1. **没有空战指挥层。** 每个基地只管“有目标就起飞”，每架飞机只管“有目标就追”。
   没有 CAP / 护航 / 打击 / 预备队的角色划分。
2. **没有波次。** 航母和机场每帧能起飞就起飞，先到先打，天然形成添油战术；先到的
   飞机被对方集中吃掉，后到的飞机没有掩护。
3. **没有护航检查。** 打击机起飞时不会等待护航战斗机，也不会因为护航不足而推迟。
4. **CAP 只是兜底。** `PlanePatrol` 只在“没有可打目标”时启用；只要场上还有敌机，
   所有战斗机都会去追，舰队上空自然没有 CAP。
5. **目标优先级偏向“高战力”而不是“高威胁”。** 对空威胁分直接取
   `CombatPower.Total / 100`，B-29/B-17 这类高血量、多炮塔的轰炸机分数很高，
   战斗机被吸过去啃轰炸机箱，而不是优先拦截来袭的打击机。
6. **没有脱离/轮换。** 战斗机只有燃油耗尽才返航，不会因为受伤、劣势或任务完成而退出；
   一波打光就是永久损失。
7. **轰炸机自卫火力没有瞄准/跟踪成本。** 见第 6 节；这会让“CAP 去拦截轰炸机”也变成
   送死，单靠 AI 分层不足以解决。

## 3. 目标行为

### 3.1 角色划分

每架起飞的飞机必须有一个明确角色，角色在起飞时确定，飞行中可转换但要有记录。

| 角色 | 兵力来源 | 任务 | 默认比例 |
|---|---|---|---|
| `cap` | 战斗机 | 在舰队威胁轴上空巡逻，拦截进入拦截圈的敌机 | 25%–35% 战斗机 |
| `escort` | 战斗机 | 跟随打击编队，优先打拦截己方打击机的敌机 | 30%–50% 打击机数量 |
| `strike` | 俯冲/鱼雷/水平轰炸机 | 编波后攻击指定敌舰 | 全部打击机，按波次投放 |
| `reserve` | 任意 | 留在甲板/机场，等 CAP 或打击波次消耗后补充 | 10%–20% |
| `scout` | 侦察机/临时侦察机 | 搜索、保持接触 | 现有侦察逻辑 |

> 玩家侧是否自动套用同样配额，需要单独定；本文先按“电脑侧默认启用、玩家侧可选”设计。

### 3.2 波次状态机

每个基地/每侧维护一个打击波次：

```text
Idle
  -> Massing      收集打击机，指定集结点；等待护航
  -> Launch       达到 minWaveSize 或 maxMassDelay，且护航比例达标
  -> Inbound      飞向目标；护航保持在打击编队附近
  -> Attack       进入投放航路，投弹/投雷
  -> Egress       脱离，护航掩护撤退
  -> Recover      返航、着舰、补充
```

建议参数（先给默认值，后续调）：

| 参数 | 默认 | 说明 |
|---|---:|---|
| `minWaveSize` | 12–24 架 | 低于这个数量不单独成波；残局可放宽 |
| `maxMassDelay` | 20–30 s | 不能无限等，超时以现有兵力出击 |
| `escortRatio` | 1 架战斗机 : 3–4 架打击机 | 不足则推迟或缩波 |
| `maxWavesInFlight` | 1–2 | 避免一次性把所有打击机倒出去 |
| `waveInterval` | 30–60 s | 两波之间的最短间隔 |
| `reserveRatio` | 0.1–0.2 | 留在甲板上的预备队 |

关键点：**波次是“按基地/按侧”协调，不是按单舰**。现在每艘航母各自起飞，同一侧的
31 艘航母会在同一分钟里各自形成小波次；应该由一个 air commander 汇总，统一决定
“这一波出多少、谁护航、打哪个目标”。

### 3.3 CAP

- **站位**：舰队质心沿“敌情方向”前出 10–18 格，绕 2–4 格半径盘旋；不是绕单艘航母。
- **拦截圈**：以舰队质心为圆心，15–25 格；敌机进入拦截圈才交战。
- **脱战**：追击离舰队超过 `capLeash`（例如 20 格）或目标进入己方舰队防空圈后，放弃追击、回站位。
- **轮换**：CAP 每 60–90 s 轮换一次；燃油低于返航余量 + 20% 时自动换班。
- **紧急升空**：发现敌方打击编队（≥3 架打击机、朝己方舰队飞）时，CAP 比例临时升到 50%–60%，
  从 `reserve` 或甲板补机；敌方打击编队脱离后恢复。

`PlanePatrol` 可以作为 CAP 的基础实现，但需要补：
- 按舰队质心而不是单基地定位；
- 拦截圈/脱战圈；
- 目标优先级（只打进入圈的威胁）；
- 与 `AirCommander` 的配额联动。

### 3.4 护航

- 护航战斗机绑定一个 `StrikePackage`，而不是全局目标队列。
- 护航的交战半径：打击编队周围 8–12 格；只打威胁打击编队的敌机。
- 打击编队被拦截时，护航优先打**正在攻击己方打击机的敌机**，而不是追远处目标。
- 护航不足时，打击波次推迟；如果敌方 CAP 太强，允许取消波次、保留兵力。

### 3.5 目标优先级（空对空）

把“威胁”拆成两个维度：

- `ThreatToFleet`：对己方舰队的威胁，主要由挂载（炸弹/鱼雷）、航向（是否朝己方舰队）、
  距离、数量决定；鱼雷机/俯冲轰炸机最高。
- `SelfDefense`：目标的自卫火力/血量，主要由炮塔数、HP、机动决定；B-29/B-17 很高。

战斗机目标排序建议：

1. 正在攻击己方舰队的打击机（`ThreatToFleet` 高）；
2. 敌方护航战斗机；
3. 敌方 CAP / 扫射机；
4. 敌方重型轰炸机/侦察机（`SelfDefense` 高且 `ThreatToFleet` 低，**最后考虑**）。

对重型轰炸机的额外规则：
- 没有局部数量优势（例如 2:1 以上）不主动进攻；
- 优先从侧前方/高空进入，避免尾追进入后射界；
- 用 `maxAirAttackersPerTarget` 集火，而不是一架一架送。

> 现有 `Threat = CombatPower.Total/100` 会把 B-29 排到最前，需要改成上面的双维度评分；
> 这是“战斗机为什么去啃轰炸机”的直接原因。

### 3.6 脱离与轮换

- 战斗机 HP < 30%、燃油 < 返航余量 + 20%、或目标进入己方舰队防空圈且没有胜算时，脱离回舰。
- 打击机在护航损失过半、或目标 CAP 明显占优时，允许取消攻击、返航（不强制投弹）。
- 返航后进入 `Recover`，补给后重新编入 CAP/护航/预备队；不要“打光为止”。

### 3.7 与舰队 AI 的接口

舰队 AI 目前只关心水面编队（`pkg/mission/controller/computer/strategy.md`）。空战指挥层需要
向舰队 AI 提供：

- 当前 CAP 覆盖（舰队上空有多少战斗机、拦截圈是否完整）；
- 敌方打击编队是否正在接近；
- 本侧是否还有可用打击波次。

舰队 AI 可以据此调整：
- CAP 不足时，航母向己方掩护方向靠拢/加速；
- 发现敌方打击编队时，舰队转向减少被咬尾；
- 没有打击能力时，优先防守而不是继续前压。

第一版可以只做“air commander 读舰队位置”，暂不反向影响舰队 AI。

## 4. 实现拆分

### 4.1 模块划分

建议新增一个空战指挥层，放在 manager 侧，不新建顶层包：

```text
pkg/mission/manager/
  air_ops.go          // AirCommander：角色分配、波次状态机、CAP/护航配额
  air_ops_test.go
  air_metrics.go      // 观测指标（P0）
```

- `AirCommander` 每侧一个，挂在 `MissionManager` 上；
- 复用现有 `Instr`：`PlaneAttack`、`PlanePatrol`、`PlaneReturn`；
- 新增 `PlaneEscort` 或给 `PlaneAttack` 增加 `role/leash/packageID` 字段；
- 不改变 `targeting.BuildPlan` 的纯函数性质；空战指挥层只消费/覆盖它的队列。

### 4.2 数据结构草案

```go
type AirRole string // cap | escort | strike | reserve | scout

type AirOrder struct {
    PlaneUID  string
    Role      AirRole
    PackageID string
    Station   objPos.MapPos // CAP 站位 / 集结点
    Leash     float64       // 脱战半径
    TargetUID string
}

type StrikePackage struct {
    ID         string
    TargetUID  string
    Strike     []string // plane uids, ordered
    Escort     []string
    State      PackageState
    MassSince  int64
    LaunchedAt int64
}

type AirDoctrine struct {
    CAPRatio       float64
    EscortRatio    float64
    ReserveRatio   float64
    MinWaveSize    int
    MaxMassDelay   int64 // ticks
    WaveInterval   int64
    CAPLeash       float64
    CAPStationDist float64
    RetreatHP      float64
    RetreatFuel    float64
}
```

确定性要求：
- 所有 map 遍历按 UID 排序，或复用现有 `OrderedPlanes/OrderedShips`；
- 不引入 map 迭代顺序影响结果；
- 每 30 拍更新一次指挥官状态，避免每帧全场扫描；
- 新增指标写入 `sim` 的 metrics/findings，便于回归。

### 4.3 配置

优先给每关一个可选的 `airDoctrine`，缺省用阵营默认值：

```json5
airDoctrine: {
  capRatio: 0.3,
  escortRatio: 0.3,
  reserveRatio: 0.15,
  minWaveSize: 16,
  maxMassDelay: 30,
  waveInterval: 45,
  capLeash: 20,
  capStationDistance: 12,
  retreatHP: 0.3,
  retreatFuel: 0.25,
}
```

不建议第一版就做 20 个参数；先固定 5–6 个，跑出基线再调。

### 4.4 分阶段

**P0：只观测，不改行为（1 个 PR）**
- 给每架飞机记录 `role`（先由机种推断：fighter→cap/escort 未定，bomber→strike）；
- 输出指标：CAP 覆盖数、打击波次数量/大小、护航比例、战斗机损失中 bomber 占比、
  首次敌打击到达时舰队上空战斗机数；
- 不改任何指令，确保现有 F3 基线不变。

**P1：CAP / 护航配额（MVP）**
- 起飞时按比例分配 CAP/护航/打击；
- CAP 用 `PlanePatrol` 的站位/拦截圈，不再“有目标就全追”；
- 打击机起飞前检查护航，不足则等待；
- 目标：首波敌打击到达时舰队上空至少有 4 架 CAP；战斗机损失中 bomber 占比下降。

**P2：波次协调**
- 引入 `StrikePackage` 和 `Massing/Launch/Inbound/Attack/Egress/Recover`；
- 达到 `minWaveSize` 或超时出击；同一时间最多 1–2 波；
- 目标：一场战斗至少 2–3 个可辨识的打击波次，而不是一次全员冲锋。

**P3：目标优先级 / 脱离**
- 双维度威胁评分；重型轰炸机降权；
- 受伤/燃油/劣势脱离；
- 目标：战斗机不再主动送进 B-29 炮塔阵；损失交换改善。

**P4：调参与表现**
- 每关/每阵营 doctrine；
- UI/调试面板显示 CAP、波次、护航；
- 平衡回归。

## 5. 验证方案

### 5.1 场景

| 场景 | 用途 |
|---|---|
| `MidwayAllTypesDuelTest` | 主回归：31v31 航母、全机型；检查波次、CAP、交换比 |
| `PearlHarbor1941` | 单方面空袭回归：不能因为 CAP 逻辑让进攻方完全打不动 |
| 新增 `air-cap-duel` | 1 航母 + 4 战斗机 + 4 打击机 vs 1 航母；确定性地测 CAP/护航 |
| 新增 `bomber-box` | 1 B-29 vs 4 A6M2；测自卫火力，不涉及舰队 AI |

### 5.2 指标

- `cap_coverage_at_first_strike`：敌方首波打击到达时，舰队 20 格内的己方战斗机数。
- `strike_waves`：≥3 架打击机且朝同一目标的波次数。
- `mean_wave_size` / `max_wave_size`。
- `escort_ratio`：护航战斗机 / 打击机。
- `fighter_loss_share_to_bombers`：战斗机损失中死于轰炸机/攻击机的比例。
- `time_to_first_ship_loss`。
- `planes_launched / planes_available`。
- `tick_p99_ms`（性能门禁）。

### 5.3 验收线（建议）

- 任一侧在首次接触后 60 s 内损失不超过 40% 战斗机（当前轴心约 90% 在 120 s 内）。
- 每侧至少 2 个打击波次；单波不超过该侧打击兵力的 60%。
- 首波敌打击到达时，舰队 20 格内至少有 4 架 CAP。
- 战斗机损失中 bomber 占比 < 30%（当前 47%）。
- 战斗时长 ≥ 4 分钟（当前 2.5–3 分钟）。
- 同 seed 可复现；`tick_p99 < 16.7 ms`。

> 这些是“行为验收”，不是“轴心国必须赢”。轴心国仍可能因为机型代差输，但输的过程应该是
> 多波次、有 CAP、有护航的消耗，而不是 2 分钟一次团灭。

## 6. 关联修复：轰炸机自卫火力

### 6.1 为什么轰炸机击杀效率高

不是“跟踪瞄准时间太长”，而是**轰炸机炮塔没有跟踪/瞄准时间，战斗机有**：

- `Gun.Fire` 只检查 `Reloaded` + `InShotRange`（射程 + 当前机头射界），没有炮塔转动、
  目标获取、跨目标切换的延迟。
- `updatePlaneDefensiveFire` 每帧选 1 架敌机，然后 `Plane.Fire` 让**所有已装填炮塔**
  同时对它开火。
- 重型轰炸机的射界数据接近全向：B-29 的 5 个炮塔里 3 个是 360°，后 2 个覆盖 160°；
  尾追时 5 个炮塔、12 挺 12.7mm 全部能开火。
- 战斗机的前射机炮只有 ±20°，必须把机头转过去；轰炸机可以保持平飞，炮塔“瞬间”开火。
- 重型轰炸机的有效 HP 很高：B-29 135 HP / 0.5 减伤 = 270 有效 HP；B-17 230；
  He177 276。战斗机 A6M2 只有 37 有效 HP。

TTK 对比（纸面，全部命中）：

| 对战 | 轰炸机击杀战斗机 | 战斗机击杀轰炸机 |
|---|---:|---:|
| B-29 vs A6M2 | 37 / 60 ≈ **0.6 s** | 270 / 38 ≈ **7.1 s** |
| B-17 vs A6M2 | 37 / 45 ≈ 0.8 s | 230 / 38 ≈ 6.1 s |
| B-26 vs A6M2 | 37 / 30 ≈ 1.2 s | 150 / 38 ≈ 3.9 s |
| B-29 vs F6F | 100 / 60 ≈ 1.7 s | 270 / 30 ≈ 9.0 s |

所以一架 A6M2 尾追 B-29 是必死；即使 4 架集火，B-29 也能在被打掉前换掉 1–2 架。
这解释了 8 架 B-29 能击落 39 架轴心战斗机、B-17 8 架击落 28 架。

再拆一层：416 架“死于轰炸机/攻击机”的轴心战斗机里，**347 架（83%）死于炮塔/机枪火力，
69 架（17%）死于炸弹直击或破片**。B-29 的 39 架战果里 27 架是炮塔、12 架是炸弹；
B-17 是 15 + 13；B-26 是 8 + 15。也就是说：

- 炮塔火力是主因，约占全部战斗机损失的 39%（347/884）；
- 炸弹破片是次要但不可忽略的来源，约占 8%（69/884），来自水平轰炸机对舰投弹时
  把目标舰附近的战斗机一起炸掉——这也是为什么“战斗机去咬轰炸机”经常有去无回。

### 6.2 可选修复

按“改动小、收益大”排序：

1. **炮塔跟踪时间**：每个炮塔对当前目标有 `aimTicks`（0.5–1.0 s），换目标重置；
   交叉目标更长。`Gun` 增加 `AimTargetUID/AimStartTick`，`Fire` 前检查。
2. **限制同时开火的炮塔数**：一架轰炸机对单个目标最多 2–3 个炮塔开火，其余炮塔
   冷却/转移目标；避免 12 挺枪瞬间集火。
3. **收窄射界**：把 B-29/B-17 的机首/中部炮塔从 360° 改成前向/侧向有限射界；
   至少让尾追不是“全炮塔都能打”。
4. **命中精度惩罚**：对高角速度/高速度目标增加散布或提前量误差；现在的提前量是完美的。
5. **耐久/伤害调整**：降低重型轰炸机 HP/减伤，或给战斗机对轰炸机增加伤害系数
   （例如 1.5×），让 2–3 架战斗机能在 4 s 内打掉一架 B-29。
6. **AI 规避**：配合第 3.5 节，战斗机不主动尾追重型轰炸机；优先打来袭打击机。

建议第一版组合：**2（限制炮塔数）+ 5（降耐久/加对轰炸机伤害）**，先把 TTK 拉到
“单机打不过、3 架能打过”；跟踪时间（1）作为第二版，避免一次改太多。

单独加跟踪时间不够：B-29 对 A6M2 的 TTK 只有 0.6 s；给 1 s 瞄准延迟，零式也只多打约
1 s（约 27 点有效伤害，B-29 有效 HP 270），仍然换不掉。跟踪时间必须和 2/5 一起用。

## 7. 风险与开放问题

- **确定性**：新增指挥官状态、map 遍历、目标切换都必须按 UID 排序；F3 的同 seed 复现是硬要求。
- **性能**：每 30 拍一次全场快照可以接受；不要每帧为每架飞机做全场扫描。
- **玩家可读性**：CAP 盘旋、波次等待需要 UI 提示，否则玩家会以为飞机“卡住”。
- **平衡**：CAP/护航会让强势方更强；需要用 `airDoctrine` 做阵营差异，而不是一套参数通吃。
- **玩家侧**：玩家手动操作与 AI 配额如何共存？建议玩家侧默认关闭自动波次，只提供 CAP 快捷键。
- **与现有 `PlanePatrol` 的关系**：是扩展它，还是新建 `PlaneEscort`/`AirOrder`？建议先扩展
  `PlanePatrol` 的站位/拦截圈，再引入 `AirCommander`。
- **高度**：当前是 2D，没有高度差；如果未来加高度，B-29 的炮塔射界和战斗机攻击角会变，
  本文的 TTK 需要重算。
- **修复顺序**：先 P0 观测 → P1 CAP/护航 → P2 波次 → P3 目标/脱离；不要先调数值，
  否则无法区分“AI 行为改善”和“数值改动”。
