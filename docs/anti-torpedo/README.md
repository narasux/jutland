# 机炮反鱼雷设计（Autocannon Anti-Torpedo Defense）

> 状态：已实现（2026-11-24），2026-11-24 第二轮调整：无差别择敌 + 舰种火控分档 + 鱼雷战斗部诱爆系数；2026-11-26 第三轮：航空投放鱼雷的诱爆修正。
> 本文记录当前规则、实现链路与取舍，供后续调平衡和扩展。代码位置以文件 / 函数名为准，行号会漂移。

**一句话**：舰上的小口径自动炮会打射程内最近的敌方鱼雷，拦截强度按舰种分档——
驱逐舰能靠它搏一条命，主力舰只把它当最后一道近防。

## 1. 目标与非目标

### 目标

- 给舰船一个**近程、低概率、不依赖新配置字段**的鱼雷自卫手段。
- 复用现有防空炮的射界、射程、装填、散布与提前量计算，不另写弹道。
- 让“机炮反鱼雷”有可见表现（小水花），但不改变鱼雷命中舰船时的伤害结算。
- 让**小舰反鱼雷强、主力舰反鱼雷弱**：驱逐舰不会看见鱼雷就只能等死，主力舰也不会因为
  防空炮座多就变成鱼雷免疫。
- 让**轻雷比重雷好拦**：航空鱼雷 / 轻型反潜雷更容易被机炮诱爆，610mm 氧气雷与回天更难。
- 不显著增加每拍开销，不在热路径引入堆分配。

### 非目标

- 不做史实级拦截概率；二战舰炮反鱼雷本身命中率很低。
- 不做**舰队级目标分配**（不判断“这枚雷该由谁负责”）：任何在射程内的舰都可以对最近的
  敌雷开火，天然形成护航舰替主力舰挡雷，但没有协同、没有抢占、没有通讯。
- 不做鱼雷耐久 / 多段命中 / 引信损伤模型；仍然是“穿过命中框后单发概率引爆”，
  只是这个概率乘了战斗部系数与投放修正。
- 不新增图鉴战力项、战报条目、拦截统计或专门 UI。
- 不为每座炮单独配置反鱼雷开关；按口径自动推导。
- 不做自动规避。鱼雷规避仍由玩家转向完成，本文只解决“拦不拦得住”。

## 2. 玩法规则

### 2.1 哪些炮能反鱼雷

初始化阶段按“**对空 + 弹径 ≤ 40mm**”自动标记：

```text
AntiTorpedo = AntiAircraft && bullet.Diameter <= 40
```

- 覆盖 12.7 / 13 / 20 / 23 / 25 / 28 / 30 / 37 / 40mm 等小口径炮。
- 57mm 六磅炮及更大口径不参与；127mm 等高平两用炮不参与。
- `guns.json5` 不新增字段，推导逻辑在 `initGunMap`。
- 舰船初始化时把所有可反鱼雷炮的最大射程汇总到 `ShipWeapon.MaxToTorpedoRange`。

这是最大的隐式规则：**改口径阈值会直接改变所有舰船的反鱼雷能力**。

### 2.2 目标选择（无差别择敌）

每拍由 `MissionManager` 收集一次仍在航行的鱼雷（`TypeTorpedo`、未命中、`Life > 0`），
舰船只在火控就绪时查找目标：

- 敌我过滤：只打敌方鱼雷；友军鱼雷不拦。
- 射程：鱼雷到本舰中心距离 ≤ `MaxToTorpedoRange`（还要满足炮自身射界 / 射程）。
- 射界：至少有一座可用反鱼雷炮能把炮口转向该方位（`BattleShip.CanBearAntiTorpedo`）。
  没有这一条，最近的那枚雷落在射界外时会把火控卡住，直到它自己漂出射程；
  真正冲本舰来的鱼雷就被晾在一边了。只查射界，不查提前量，边界处偏保守。
- 多目标：取**距离最近**的可打到敌雷。

**不再判断“鱼雷航迹是否穿过本舰”**。理由：

1. 机炮手看到贴水鱼雷就打，本来不会去算“它是不是冲我来的”。
2. 驱逐舰一边转向规避一边开火时，航迹判定会突然失效、反鱼雷炮直接停火——
   这正好惩罚了会机动的小舰，是旧版“驱逐舰等死”的来源之一。
3. 护航舰会顺手打朝主力舰去的雷，形成**被动舰队掩护**，不需要舰队级目标分配。
4. 少一次点击式的几何判定，见 [6. 性能](#6-性能)。

代价：每秒一次的拦截机会可能花在一枚本来擦身而过的鱼雷上；这是有意接受的浪费。

### 2.3 开火

反鱼雷优先于对空：

1. 若本舰火控就绪且有敌雷在射程内，先尝试反鱼雷。
2. 一次只动用**一座炮**，按防空炮 → 副炮 → 主炮的顺序找第一座能开火的炮。
3. 该炮走正常的 `Gun.Fire`：提前量、射程、射界、散布、装填全部沿用。
4. 成功开火后，整舰进入**按舰种决定的火控间隔**（见 2.4 / 4）。
5. 若所有炮都因射界 / 射程 / 装填无法开火，则不消耗冷却，下一拍继续尝试。

关键点：**不是每座炮各自冷却，而是整舰按火控间隔组织一次拦截**。否则战列舰十几座
防空炮会轮流开火，等效射速随炮座数线性增长，重新变成“大舰鱼雷免疫”。

舰种分档让同样一门 40mm 四联在驱逐舰上能在 3 格射程窗口（约 0.8 秒）内打出两轮，
在战列舰上只够打一轮——这是“小舰反鱼雷更强”的第一个来源。第二个来源是单发概率。

### 2.4 命中与表现

反鱼雷炮弹在发射时记录目标鱼雷指针（`Bullet.TargetTorpedo`），并把发射舰的火控质量
写进 `Bullet.AntiTorpedoChance`。命中结算只检查这一条鱼雷，不做“炮弹 × 全场鱼雷”的
二次遍历。

每拍结算：

- 用本拍炮弹扫过的线段与鱼雷小矩形（`0.08 × 0.03` 地图格，约 10m × 4m）做相交。
- 相交后按下面的概率掷**一次**骰：

  ```text
  P(单发引爆) = 发射舰火控概率（按舰种） × 鱼雷战斗部诱爆系数（按伤害）
  ```

- 一发炮弹只对锁定的鱼雷掷一次骰（掷完清空 `TargetTorpedo`）。命中框很窄，同一发弹
  可能在连续两拍都压在同一条鱼雷上，重复掷骰会让实际概率翻倍、调参失真。
- 成功：目标鱼雷和炮弹都标记为 `TypeTorpedo` 命中；鱼雷在**本拍内**移出战场，
  炮弹进入到达列表。
- 表现：鱼雷位置生成一个小水花（`KindSplash`，`0.5` 格，`30` tick），不生成伤害数字，
  不结算舰船伤害。
- 失败：炮弹继续飞，鱼雷继续前进；这一发弹不会再次判定。

已命中的鱼雷会在 `updateShotBullets` 末尾的统一清理段中移入到达列表，避免“炮弹在鱼雷
已经推进过本拍之后才命中，鱼雷还多活一帧”。

### 2.5 鱼雷战斗部诱爆系数

鱼雷越重越难被一发小口径弹引爆，系数由弹药自带的 `damage` 与投放来源推导（不新增配置字段）：

```text
factor = clamp(4500 / damage × (航空投放 ? 1.5 : 1), 0.45, 2.2)
```

- 战斗部项表达「轻雷好打、重雷难打」；
- 投放项表达「航空雷更好拦」：空中投放的鱼雷入水姿态不稳、航速低于同代舰载雷、航迹更长，
  留给自卫火控的窗口也更大，因此同一战斗部下航空雷的诱爆系数是舰载雷的 1.5 倍；
- 两项先乘再夹紧，极轻或极重的鱼雷仍落在同一个上下限内，不会因为投放来源突破 2.2。

| 鱼雷 | damage | 舰载 | 航空投放 |
|---|---:|---:|---:|
| US Mk44 反潜雷（324mm） | 1400 | 2.20（上限） | 2.20（上限） |
| RU M1912（450mm） | 2200 | 2.05 | 2.20（上限） |
| JP 九一式二型航空雷（450mm） | 3400 | 1.32 | 1.99 |
| US Mk15（533mm） | 4300 | 1.05 | 1.57 |
| US Mk13（570mm，航空） | 4800 | 0.94 | 1.41 |
| JP 九三式一型（610mm） | 6250 | 0.72 | 1.08 |
| 回天（人操） | 24233 | 0.45（下限） | 0.45（下限） |

`damage <= 0`（手工构造的测试弹）返回 1：未知战斗部无法判断轻重，也不叠加投放修正，
避免除零或未知值把概率放大到必中。

## 3. 实现链路

### 3.1 目标类型

鱼雷原本是 `*objBullet.Bullet`，不是 `Hurtable` 战斗单位。为了复用 `Gun.Fire`：

- 在 `object.Type` 末尾追加 `TypeTorpedo`，不插在 `TypeWater` / `TypeLand` 前面，
  避免已有枚举值整体位移。
- `unit.TorpedoTarget` 适配器把一条鱼雷包装成 `Hurtable`：
  - `ObjType()` 返回 `TypeTorpedo`；
  - `MovementState()` 返回鱼雷当前位置、航向、速度；
  - `Player()` 返回鱼雷所属阵营；
  - `ID()` 只返回固定字符串，鱼雷没有独立 UID。
- `Gun.Fire` 在目标类型为 `TorpedoTarget` 时，把真实鱼雷指针写进 `TargetTorpedo`。

### 3.2 管理端

`MissionManager` 新增 / 调整：

- `antiTorpedoCandidates []*objBullet.Bullet`：每拍收集的航行中鱼雷（不再预存航向三角函数）。
- `antiTorpedoTarget unit.TorpedoTarget`：逐舰复用的目标包装，避免每舰每帧堆分配。
- `rebuildAntiTorpedoCandidates()`：每拍遍历一次 `ForwardingBullets`，只挑航行中的鱼雷。
- `nearestEnemyTorpedo(ship)`：在候选列表里按平方距离取最近敌雷，先按距离剪枝，
  再用 `BattleShip.CanBearAntiTorpedo` 排除所有炮座都转不过去的鱼雷；无航迹判定。
- `shipFireTargets`：仅当 `ship.AntiTorpedoReady()` 时才查找鱼雷目标，冷却中直接跳过。
- `updateShotBullets`：`TargetObjType == TypeTorpedo` 的命中分支改为
  `AntiTorpedoChance × TorpedoDetonationFactor()`，并保证单发只掷一次骰。
- `hitEffect`：`HitObjType == TypeTorpedo` 返回小水花。

### 3.3 舰船端

- `unit.DefaultAntiTorpedoProfile(shipType) AntiTorpedoProfile`：按舰种给出
  `FireInterval` 与 `HitChance`。
- `BattleShip.antiTorpedoReadyTick`：整舰反鱼雷火控下一次可组织拦截的拍。
- `AntiTorpedoReady()`：`SimTick() >= antiTorpedoReadyTick`。
- `BattleShip.FireAt`：反鱼雷优先，`fireOneMount` 只允许一座炮开火，成功后按 profile 写冷却，
  并给这一轮炮弹盖上 `AntiTorpedoChance`。
- `BattleShip.CanBearAntiTorpedo(pos)`：择敌用的射界预筛（防空 / 副炮 / 主炮三组里是否
  有可反鱼雷炮座覆盖该方位）。

### 3.4 弹药端

- `Bullet.AntiTorpedoChance`：发射舰写入的单发引爆概率；0 表示未标注，结算时回落到
  `antiTorpedoBaseHitChance`。
- `Bullet.TorpedoDetonationFactor()`：按 `damage` 换算的战斗部诱爆系数。

## 5. 设计取舍

### 5.1 为什么按口径自动推导反鱼雷能力

优点：零配置迁移，287 条炮配置不用动，新增舰船自动获得一致行为。

代价：规则是隐式的，舰船无法单独关闭反鱼雷；12.7mm 机枪也会被算进来（虽然射程很短）。

### 5.2 为什么“整舰一次一座炮 + 舰种火控间隔”

这是本功能最重要的平衡护栏。

最早是“所有防空炮同时打同一条鱼雷”，实测战列舰单雷拦截率极高，因为炮座数量直接乘进
射速；后来改成“每拍一座炮”，但战列舰仍有十几座炮可以轮流开火。现在是**整舰按舰种间隔
组织一次拦截，一次只允许一座炮开火**：

- 炮座数量只影响“哪座炮能打、射界覆盖好不好”，不再线性放大射速；
- 驱逐舰 0.5 秒可以在同一个射程窗口里组织两轮，战列舰 1.5 秒只够一轮；
- 单发概率再按舰种给出差距（0.08 / 0.05 / 0.03）。

代价：同一门炮在不同舰种上的表现不同，这是玩法平衡而不是史实换算。**如果坚持“炮就是炮”，
就必须放弃“小舰反鱼雷强”，二者不能同时成立**——因为大舰的炮座数量决定它天生更强。

### 5.3 为什么单发基准只有 3%~8%

反鱼雷应该像“最后一道近防”，不是可靠护盾。这个值同时承担：

- 控制单条鱼雷的突防概率；
- 控制多雷齐射时被“顺带扫掉”的数量；
- 给后续平衡留一个单点旋钮（配合 2.5 的战斗部系数）。

### 5.4 为什么允许无差别攻击（也等于允许被动替友舰挡雷）

- 实现简单：不需要“帮友舰拦截时鱼雷归属谁、战报记给谁”。
- 行为合理：机炮手不会先算航迹，看到鱼雷就打。
- 玩法收益：护航舰天然替主力舰分担，但没有任何强制性协同；玩家编队仍然有意义。
- 修正旧版缺陷：驱逐舰转向规避不再导致反鱼雷炮停火。
- 性能：少一次投影与横向距离判定，见第 6 节。

代价：可能把一次拦截机会花在擦身而过的鱼雷上；不做目标分配时多舰可能打同一枚雷。

### 5.5 为什么用炮弹指针锁定鱼雷

反鱼雷炮弹发射时记录 `TargetTorpedo *Bullet`，命中结算只检查这一条鱼雷：

- 避免每发反鱼雷弹每拍遍历全场鱼雷，复杂度从 O(炮弹 × 鱼雷) 降到 O(炮弹)。
- 鱼雷被其他炮弹提前击毁时，通过 `HitObjType != TypeNone` 直接跳过。
- 掷过一次骰后清空指针，杜绝同一发弹重复判定。

### 5.6 为什么反鱼雷优先于防空

来袭鱼雷的命中是“几秒内发生”，飞机投弹通常还有一段飞行 / 俯冲时间。首版让反鱼雷先消耗
本拍开火机会，避免舰船在鱼雷已经贴近时还在追飞机。

代价：鱼雷和空袭同时到来时，防空火力会短暂转向海面。

### 5.7 为什么不做鱼雷耐久 / 多段命中

“鱼雷血量、打几发才沉”听起来直观，但和现有几何不匹配：鱼雷命中框只有 0.08 × 0.03 格，
一轮四联齐射能穿框的弹本来就只有一两发。要做多段，就得同时放大命中框或提高单发命中，
等于把系统改成另一套模型。

现在用“单发概率 × 战斗部系数”表达同一件事：轻雷好打、重雷难打，且可以把期望命中数
连续地调到 0~2 发之间。**不要再叠加耐久层**，否则两层概率叠在一起更难调。

## 6. 性能

### 6.1 择敌开销

合成基准（Apple M1 Pro / Go 1.26.2，`-benchtime 300x`）：200 艘 real Porter 模板 × 400 条鱼雷，
每拍执行一次 `rebuildAntiTorpedoCandidates()`，再对 200 艘舰各查一次最近敌雷：

| 实现 | 每拍开销 | 分配 |
|---|---:|---:|
| 旧版（航迹走廊判定 + 预存三角函数） | 约 387 µs | 0 |
| 当前（敌我与距离 + 射界预筛） | 约 333 µs | ≤ 31 B（基准噪声，可忽略） |

约 -14%，换成真实规模（关卡最大 65 舰）时是亚微秒级差异；旧版每拍要为每条鱼雷算
`sin/cos`，现在一次三角函数都不需要（射界预筛在距离剪枝之后才执行，只对“比当前最近
更近”的少量候选生效）。真正的收益是**代码少一个几何概念**（没有“威胁走廊”需要解释和调参）。

这个基准是“每舰每拍都找雷”的上界。实际运行中只有火控就绪的舰才查询（驱逐每 0.5 秒、
主力舰每 1.5 秒），开销还要再低一到两个数量级。

### 6.2 什么时候需要再优化

如果以后出现“数百条鱼雷同时在场”的极端场景，可以把 `antiTorpedoCandidates` 改成按 4~8 格
分桶的鱼雷空间索引，逐舰只查邻域。当前规模不需要。

## 7. 平衡观测

用真实舰船配置、真实鱼雷、固定随机种子，单条鱼雷从 8 格外直冲静止本舰，每种组合 120 次：

| 舰船 | 450mm 航空雷 | 533mm Mk15 | 610mm 九三 |
|---|---:|---:|---:|
| Porter（DD，2×40mm 四联） | 34.2% | 30.8% | 22.5% |
| Baltimore（CA，40mm 四联） | 10.8% | 8.3% | 6.7% |
| Yamato（BB，25mm 三联） | 6.7% | 5.0% | 4.2% |
| Bismarck（BB，37mm 双联） | 3.3% | 3.3% | 3.3% |
| Maury（早期 DD，只有 20mm） | 3.3% | 2.5% | 2.5% |

同样两门 40mm 四联、只改舰种的对照测试：驱逐 34.0%、巡洋 11.5%、战列舰 8.5%
（每种舰种 200 次）。舰种档与战斗部档两轴叠加后，驱逐 vs 航空雷（34.2%）约是战列舰 vs 九三式（4.2%）的 8 倍。

> 上表测于 2026-11-24，当时还没有航空投放修正，航空列只体现“航空雷战斗部更轻”。
> 2026-11-26 起航空投放的鱼雷诱爆系数再乘 1.5：两门 40mm 四联驱逐舰探针实测
> （`TestAntiTorpedoAirTorpedoIsEasierThanShipTorpedo`，Mk13 4800 伤害、120 次固定种子）
> 舰载来源 37.5% → 航空投放 45.8%，+8.3 个百分点；因此上表航空列会同步上移，其余两列不变。

几点解读：

- **炮座质量仍然重要**：Maury 只有 20mm 单装，即使舰种是驱逐也拦不住几条雷。
  后期博福斯四联才是反鱼雷主力，早期驱逐仍然怕雷——这是有意的史实梯度。
- **驱逐仍然会死**：Porter 只有 1,850 HP，任何一条实战鱼雷都能一发击沉。30% 单雷拦截率
  意味着 4 雷扇面照样大概率沉没，所以不是“鱼雷免疫”，只是多了一次搏命机会。
- **主力舰的“鱼雷免疫”主要不来自反鱼雷**：Yamato 72,500 HP、水平减伤 0.55，4,800 伤害的
  鱼雷实际约 2,160，需要约 33 发才沉。反鱼雷只贡献 4%~7% 的单雷拦截。要真正提高鱼雷对
  主力舰的威胁，应该动装甲结算或鱼雷伤害，而不是继续削反鱼雷（见 8.2）。

## 8. 调参与后续优化

### 8.1 调参顺序

每次只动一个：

1. `DefaultAntiTorpedoProfile` 的舰种档（先定“驱逐 / 主力舰”两端的期望拦截率）；
2. `torpedoDetonationRefDamage` 与上下限（再定“轻雷 / 重雷”的相对差距）；
3. `torpedoAirDropFactor`（航空雷相对同战斗部舰载雷的差距）；
4. `antiTorpedoMaxCaliber`（哪些炮参与）；
5. 鱼雷命中框尺寸（目标判定宽严）；
6. 整舰火控间隔已并入舰种表，不再有单独的全局常量。

不要同时改“舰种概率 + 战斗部系数 + 口径”，否则很难从实战表现反推是哪一项造成的差异。

### 8.2 后续可做的扩展

- **鱼雷对装甲的结算**：让鱼雷走垂直减伤或 `min(水平, 垂直)`，或给鱼雷加“对主力舰伤害
  系数”。这是让主力舰真正怕雷的最直接办法。
- **自动规避**：AI 舰船（以及可选的玩家舰）在探测到来袭雷时自动转向“梳雷”，解决“人控制
  不过来这么多船”的问题。工作量大，且要处理编队保持，建议单独立项。
- **舰队掩护 / 目标分配**：给多舰共享“这枚雷已经有人负责”的信息，避免重复开火。
- **每炮配置开关**：`Gun` 增加 `antiTorpedo` 配置字段，替代口径推导。
- **战报 / 统计**：记录拦截数、拦截方、鱼雷型号；当前只有水花表现。
- **正式基准**：把临时基准固化成 `BenchmarkAntiTorpedoTargeting`，加性能门禁。

## 9. 已知限制

- 不做舰队级目标分配：多舰可能同时打同一枚最近的雷。
- 只按鱼雷当前位置做择敌与射界预筛，不预测航迹；提前量会让边界方位偏保守。
- `TorpedoTarget.ID()` 固定为 `"torpedo"`，不是唯一 UID；不用于战报归属。
- 拦截不写 observer / 战报 / 统计，只有水花表现。
- 12.7 / 13mm 机枪也会参与反鱼雷；如果觉得不合适，降低口径上限或改成显式配置。
- 反鱼雷火控冷却挂在 `BattleShip` 的运行时字段上，不参与存档（当前没有存档系统）。
- 潜艇下潜时 `gunsBlocked` 仍生效，反鱼雷炮不会开火。
- 反鱼雷炮弹不会误伤舰船 / 飞机：`TargetObjType == TypeTorpedo` 的分支只结算鱼雷。
- 单发概率乘的是舰种系数，不是炮的系数：同一门炮在驱逐舰上比在战列舰上更有效。
- 航空投放修正是全局 1.5 倍，不区分机型、投放速度与投放高度；机型差异仍由鱼雷 `damage` 承担。

## 10. 测试与验收

自动化测试：

- `TestInitDerivesAntiTorpedoForAutocannons`：真实配置下 40mm 炮可反鱼雷、127mm 炮不可，
  porter 汇总出正射程。
- `TestDefaultAntiTorpedoProfileByShipClass`：驱逐 / 巡洋 / 主力舰 / 未标注四档的间隔与概率，
  并断言驱逐档比主力舰档更快更准。
- `TestAntiTorpedoFireControlCooldownCapsVolleys`：两门炮只开一门；冷却内不重复开火；
  冷却结束后恢复。
- `TestAntiTorpedoVolleyStampsShipFireControl`：驱逐 / 战列舰的炮弹分别写入 0.08 / 0.03。
- `TestAntiTorpedoGunTargetsIncomingTorpedo`：射程内敌雷被选为 `TypeTorpedo` 目标并写入指针。
- `TestNearestEnemyTorpedoIgnoresTrackAndFriend`：直冲 / 背离 / 擦身而过都算目标；
  友军鱼雷与射程外鱼雷不算；多条敌雷取最近；正后方射界外的近雷会被跳过。
- `TestAntiTorpedoDestroyerOutperformsBattleship`：同样炮座下驱逐拦截率至少高出 15 个百分点，
  且驱逐落在 15%~55%、战列舰落在 1%~15%。
- `TestAntiTorpedoAirTorpedoIsEasierThanShipTorpedo`：同一 Mk13 只改投放来源，
  驱逐舰拦截率由 37.5% 升到 45.8%，且航空雷仍不超过 55%（不是必拦）。
- `TestAntiTorpedoHitDestroysTorpedo` / `TestAntiTorpedoProbabilityGateKeepsTorpedo`：
  命中框相交 + 概率通过 / 不通过两条真实时间线。
- `TestTorpedoDetonationFactor`：航空雷 1.32、基准 1、重雷 0.72、回天 0.45、轻雷 2.2、零伤害 1。

手动验收：

1. 进入有战列舰 + 驱逐舰的关卡，让驱逐舰向战列舰发射鱼雷。
2. 观察鱼雷接近时是否偶发小水花、鱼雷是否消失。
3. 对比开启 / 不开启拦截时的掉血；单条鱼雷应大概率命中，不应出现“整轮齐射全被扫掉”。
4. 让一艘驱逐舰横穿友舰前方的鱼雷航迹，确认它会开火――旧版此时不会。
5. 驱逐舰转向规避时确认反鱼雷炮仍在工作（旧版航迹判定会停火）。
6. 用鱼雷机攻击驱逐舰与战列舰各一轮，确认航空雷被拦下的比例明显更高。
