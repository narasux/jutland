# targeting

`targeting` 负责任务内的攻击目标规划。它只处理不可变快照并返回基地级目标队列，
不直接访问或修改 `MissionState`、指令集、Game loop 或 Ebiten 对象。

目标：让机场、航母和空中重分配使用同一套择敌策略，同时避免在主循环中进行全场
扫描、评分和排序。

## 数据流

```text
MissionManager
  -> buildTargetingSnapshot()
  -> go BuildPlan(snapshot)
  -> Plan
  -> 主线程非阻塞获取
  -> 机场 / 航母 / 空中飞机消费基地队列
```

`BuildPlan` 是纯函数，可以安全放到 goroutine 中执行。后台任务只读取 snapshot，
不会与主循环共享可变地图或对象指针。

## 核心类型

### Snapshot

`Snapshot` 是主线程在某个模拟帧创建的只读输入：

- `Tick`：创建快照时的模拟帧。
- `Bases`：需要分配目标的机场和航母。
- `Planes`：当前在场飞机及其已有目标。
- `EnemyShips`：参与舰队聚类的敌舰。
- `EnemyPlanes`：可参与对空规划的在空敌机。

`Base.Groups` 只保留目标类型、可出击数量和机型运行时总航程。主线程构建快照时，
会从 `PlaneMap` 读取已经完成初始化缩放的 `Range`。

### Plan

`Plan` 是后台返回的目标队列：

```text
Plan.BaseQueues[baseUID][targetType] = []TargetRef
```

每个基地、每种目标类型最多保留 `MaxQueueSize = 12` 项。主线程按游标顺序消费，
不重新排序或评分。

### TargetRef

- `UID`：目标舰船或敌机 UID。
- `FleetID`：对舰目标所属舰队；对空目标为空。
- `TargetType`：`TypeShip` 或 `TypePlane`。
- `Score`：生成该队列项时的评分，便于调试。

## 舰队聚类

对舰规划先按阵营分别聚类敌舰：

- 使用连通分量算法。
- 两艘敌舰距离小于等于 `FleetClusterRadius = 20` 格时归入同一舰队。
- 舰队 ID 使用该舰队中最高价值舰船的 UID 生成：`fleet:<shipUID>`。
- 聚类和后续评分都在后台执行。

当前不要求任务配置增加显式舰队 ID。

## 基地队列容量

每个基地、每种目标类型的队列长度：

```text
queueLimit = min(
    12,
    当前同类在空飞机数 + 同类可出击飞机库存
)
```

这个值同时决定该基地近期可能需要多少个目标，避免为没有飞机的基地生成无意义队列。

## 对舰评分

对舰目标以“舰队”为单位评分：

```text
score =
    0.35 * 分配均衡
  + 0.30 * 舰船价值
  + 0.25 * 基地距离
  + 0.10 * 威胁
```

其中：

- 分配均衡：当前已经追击该舰队的飞机越少，分数越高。
- 舰船价值：航母 > 战列舰 > 巡洋舰 > 驱逐舰/护卫舰 > 快艇/其他。
- 基地距离：舰队中最近可达舰距基地越近，分数越高。
- 威胁：舰队高价值目标越多、距离基地越近，分数越高。

海军价值当前为:

| 舰种 | 价值 |
|---|---:|
| 航空母舰 | 1.00 |
| 战列舰 | 0.85 |
| 巡洋舰 | 0.60 |
| 驱逐舰 / 护卫舰 | 0.35 |
| 鱼雷艇 | 0.20 |
| 其他 | 0.10 |

### 覆盖优先

对舰队列不是简单按单舰评分排序，而是分两步生成：

1. **覆盖阶段**
   - 为每个舰队挑选最合适的基地。
   - 每个舰队至少放入一个基地队列。
   - 使用 `coverageLoadPenalty = 0.12` 降低同一基地连续获得多个舰队的概率。
2. **填充阶段**
   - 覆盖归属只用于保证舰队均衡，不限制其他基地出击。
   - 每个有对舰能力且目标在航程内的基地都会独立填充。
   - 同一舰队中的舰船按“可达舰优先、价值优先”排列。
   - 每个队列最多 12 项。

这样可以避免左右机场永远只锁定地理上最近的单个舰队，也避免未拿到舰队
归属的航母或机场得到空对舰队列，只能重复起飞战斗机。

## 对空评分

对空目标按单架敌机评分：

```text
score =
    0.40 * 分配均衡
  + 0.35 * 威胁
  + 0.25 * 基地距离
```

- 当前已被更多基地分配的敌机，后续分数降低。
- 威胁来自飞机的图鉴综合战力。
- 只考虑在空敌机。

## 航程语义

飞机的 `Range` 是运行时完整单程续航池：

- 初始化时 `planes.json5.range` 会除以 8，写入 `Plane.Range`。
- 飞机飞行时扣减 `RemainRange`。
- `MustReturn()` 只在 `RemainRange <= 0` 时强制返航。
- 调度器不会额外按 `45%` 或往返半径缩减目标范围。

对舰队列只收录基地实际可达的舰：

- 规划范围取该基地同目标类型、当前有库存机型中的最大完整 `Range`，避免短腿
  机型把长航程轰炸机可打击的目标整体过滤掉。
- 实际起飞时按目标距离选择航程足够的机型编组；短腿机型不会领取超出自身
  `Range` 的任务。
- 舰队代表按“高价值优先”选择，但只从可达舰中挑选；最高价值舰超出范围时会顺延到下一艘可达舰。
- 填充队列时逐舰检查距离，超出范围的舰不会进入队列。

已起飞飞机重新选目标时，主线程会再次按飞机当前 `RemainRange` 校验目标距离。

## MissionManager 集成

`MissionManager` 只负责低频快照和 O(1) 队列消费：

- `ReplanIntervalTicks = 30`：最多每 30 个模拟帧提交一次后台规划。
- `PlanTTLTicks = 180`：无事件时计划最多保留 180 个模拟帧。
- 同一时刻最多存在一个后台规划任务。
- 后台通过容量为 1 的 channel 返回结果，主线程非阻塞获取。
- 目标沉没、敌军新增、基地队列耗尽和飞机重新选目标时标记计划失效。

主线程消费计划时使用 `BaseQueues` 游标：

- 跳过已沉没目标。
- 目标距离超过当前 `RemainRange` 时继续向后查找。
- 队列耗尽后标记计划 dirty，等待后台重算。
- 已起飞飞机已经锁定目标时，不会因为新计划到来而频繁切换目标。

## 出击编组轮转

目标类型规划之外，出击入口还负责避免单一机型垄断：

- 航母在“对空目标”和“对舰目标”之间轮转。
- 同一目标类型下，在多组可用机型之间轮转，例如 `D3A1 -> B5N2`。
- 如果目标超出当前编组航程，则继续寻找航程足够的编组。
- 起飞点白名单仍然优先；不符合白名单的编组不会占用该起飞点。

这一层位于 `MissionManager` 和 `ShipAircraft`，不在 `BuildPlan` 内。

## 飞机攻击生命周期

飞机从起飞到返航按以下流程运行：

```text
基地目标队列
  -> takeOffFromBase 选择目标类型和可到达目标的机型
  -> PlaneAttack 指令绑定目标
  -> 每帧追击并计算武器提前点
  -> 武器射程 / 射界 / 装填满足后开火
  -> 对舰武器释放完成或飞机必须返航
  -> 重新领取基地队列目标，或执行 PlaneReturn
```

### 起飞与领任务

- 航母和机场共用 `takeOffFromBase`。机场每帧最多发起两次起飞尝试，航母每次
  更新发起一次。
- 基地在可用目标类型之间轮转，例如先检查对空，再检查对舰。
- 同一目标类型内按机库顺序轮转可用机型编组。
- 选定目标后计算基地到目标的距离，只允许运行时 `Range` 足够到达该目标的
  编组起飞。未配置运行时航程的测试模板不会被提前过滤。
- 飞机成功起飞后才推进基地目标游标。起飞被冷却或机型限制阻止时，游标保持
  不变，下一帧继续尝试。

### 追击与目标粘性

- `PlaneAttack` 每帧把 `CurAttackTarget` 设置为指令目标。
- 已起飞飞机不会因为后台计划版本更新而主动改目标。
- 追击方向使用武器弹速计算提前点，战斗机的速度会根据目标速度调整。
- 当前目标沉没、离开任务状态，或距离超过飞机当前 `RemainRange` 时，主线程
  才会清除目标并重新消费基地队列。
- 对舰飞机的炸弹或鱼雷完成一次释放后，当前攻击指令结束。飞机还有未使用武器
  时会领取下一个目标，否则返航。
- 战斗机对空会持续追击，直到目标被击落、失效、超出航程或自己必须返航。

### 开火选择

- 开火层优先使用 `CurAttackTarget`，前提是目标仍在对应武器的最大射程内。
- 当前目标不可用时，才会扫描其他候选。候选选择是随机的，不重新执行基地
  规划评分。
- 对舰飞机在空中遭遇敌机时，会使用可用自卫机枪或机炮还击，但不会因此放弃
  原对舰任务。
- 最终能否发射仍由具体武器的最大射程、射界、装填状态和武器类型决定。

### 返航条件

- `RemainRange <= 0` 时强制返航。
- 对舰飞机所有炸弹、鱼雷和火箭弹均已使用后返航。
- 当前没有可分配目标，或基地队列中的目标都超出飞机剩余航程时返航。
- 返航飞机依次执行待场、进近、着舰或着水阶段，完成后恢复基地库存。

## 当前限制

- 舰队使用空间连通分量，不读取任务中的舰队 ID。
- 对空规划只处理空中敌机，不处理停机坪、滑跑中的地面目标。
- 计划只提供目标建议，实际开火仍由武器射程、射界、装填和伤害逻辑决定。
- 飞机仍保持任务级目标粘性，不在新计划到达时强制改目标。
- 鱼雷机因陆地遮挡放弃当前投放对象时，会随机选择其他敌舰，不再消费基地队列。
- 当前目标不在武器射程内时，开火层仍会扫描候选目标；这部分尚未接入后台计划。

## 测试与基准

```bash
go test ./pkg/mission/targeting
go test ./pkg/mission/targeting -run '^$' -bench BenchmarkBuildPlan
```

测试覆盖：

- 四角舰队空间聚类。
- 左右机场覆盖全部舰队。
- 所有满足库存与航程条件的基地都获得对舰队列。
- 短航程目标过滤。
- 舰队最近可达舰代表选择。
- 快照不被 `BuildPlan` 修改。

基准输入为 60 艘舰船和 200 架飞机。
